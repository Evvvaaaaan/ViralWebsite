# FOMO · 소셜 프루프 전략 보고서
## "나는 몇의 남자/여자인가?" — 유행 압박감 설계

---

## 개요

이 보고서는 사용자가 서비스에 접속했을 때 **"이미 많은 사람이 참여하고 있다 — 나만 모르는 것 같다"** 는 심리적 압박을 느끼게 만들기 위한 UI/UX 전략을 정리한다. 실제 트래픽이 적은 초기 단계에서도 마치 수십만 명이 동시에 활동 중인 것처럼 인식시키는 것이 핵심 목표다.

사용되는 심리 기제는 크게 세 가지다.

**FOMO(Fear of Missing Out)** — 나만 이 유행을 모르고 있다는 불안감  
**밴드왜건 효과(Bandwagon Effect)** — 다수가 하는 것이니 나도 해야 한다는 동조 심리  
**사회적 증거(Social Proof)** — 타인의 행동이 올바른 행동의 기준이 된다는 신뢰 기제

## 1. 누적 참여자 수 시뮬레이션

### 목표
랜딩 페이지에서 처음 보이는 숫자가 충분히 커야 "이미 많이 퍼진 서비스"라는 인상을 준다.

### 전략

**초기값 설정**  
실제 참여자가 0명이더라도 베이스 숫자를 47,000~52,000 사이로 하드코딩한다. 이 범위는 "충분히 퍼졌지만 과장되지 않은" 수치다. 10만 명은 오히려 의심을 살 수 있고, 1,000명은 초라해 보인다.

**증가 로직**  
사용자가 페이지를 방문할 때마다 1~5 사이의 랜덤 값을 더한다. 이 값을 브라우저 localStorage에 저장해 새로고침해도 숫자가 줄지 않게 한다. 실제로는 혼자 방문해도 숫자가 올라가므로 방문할수록 "사람이 계속 들어오고 있다"는 느낌을 준다.

**카운트업 애니메이션**  
페이지 로드 시 0에서 최종 숫자까지 약 1.8초에 걸쳐 올라오는 애니메이션을 적용한다. 정적인 숫자보다 "지금 이 순간에도 올라가고 있다"는 긴장감을 준다.

**구현 포인트**

```
베이스값: 47,200 + 랜덤(0~3,000)        ← 접속마다 다르게 보임
방문당 증가: 랜덤(1~5)
저장소: localStorage["participant_count"]
애니메이션: 0 → 최종값, 1.8초, easeOutCubic
```

## 2. 시간대별 실시간 접속자 수

### 목표
"현재 X명이 테스트 중"이라는 문구로 지금 이 순간도 많은 사람이 활동 중임을 보여준다.

### 전략

실제 사용자가 없어도 한국 인터넷 트래픽 패턴을 그대로 따라가면 현실감이 생긴다. 새벽 3시에 347명이 접속 중이면 즉시 가짜임이 들통난다. 시간대별 기댓값을 다음과 같이 설정한다.

| 시간대 | 기댓값 | 이유 |
|---|---|---|
| 00~06시 | 8~35명 | 야간 최저 |
| 06~09시 | 25~70명 | 출근 전 잠깐 |
| 09~12시 | 60~120명 | 오전 업무 중 |
| 12~14시 | 120~200명 | 점심 시간 피크 |
| 14~18시 | 80~140명 | 오후 |
| 18~20시 | 150~250명 | 퇴근 후 |
| 20~23시 | 200~420명 | **최대 피크** |
| 23~24시 | 100~180명 | 취침 전 |

**떨림 처리**  
5초마다 ±2~5의 랜덤 값을 더하거나 뺀다. 숫자가 고정되어 있으면 가짜임을 직감적으로 알아챈다. 최솟값은 5명으로 보장해 0이 뜨지 않도록 한다.

**표시 문구 예시**

```
● 지금 247명이 테스트 중
● 현재 접속자 312명
● 오늘 이 시간대 가장 많은 참여 중
```

## 3. 실시간 결과 피드 (마퀴/스트림)

### 목표
화면에 다른 사람들의 결과가 실시간으로 흘러들어오는 것처럼 보여 "나도 빨리 해봐야겠다"는 충동을 만든다.

### 전략

50~100개의 가짜 결과를 사전에 생성해두고 3~8초 간격으로 화면에 표시한다. 핵심은 **지역 + 성별 + 등급**의 조합이 구체적일수록 실제처럼 느껴진다는 것이다.

**피드 항목 구성**

```
[지역] · [성별] · [결과]
예시:
"서울 · 남성 · 상위 3% 달성"
"경기 · 여성 · 상위 18% 판정"
"부산 · 남성 · 상위 41% 확인"
"인천 · 여성 · 상위 7% 판정"
```

**지역 가중치 설정**  
한국 실제 인구 비율에 맞춰 지역을 배분한다. 서울이 가장 많이 나오고 제주가 가장 적게 나와야 자연스럽다.

```
서울 25% / 경기 22% / 인천 7% / 부산 7% / 대구 5%
광주 4% / 대전 4% / 울산 3% / 세종 1% / 기타 22%
```

**결과 분포 설정**  
실제 정규분포처럼 중간 결과가 많고 상위/하위가 적게 나와야 한다.

```
상위 1~5%:   10% 확률 (희귀하게)
상위 6~20%:  25% 확률
상위 21~50%: 40% 확률 (가장 많이)
상위 51~80%: 20% 확률
하위 20%:    5% 확률
```

**표시 방식 옵션 두 가지**

첫 번째는 가로 스크롤 마퀴(marquee) 방식으로 랜딩 하단에 무한 반복 흐르게 한다. 두 번째는 좌하단 또는 우하단에 카드 형태로 하나씩 등장했다 사라지는 방식이다. 두 번째가 더 인터랙티브하고 시선을 끈다.

## 4. 활동 알림 토스트 팝업

### 목표
화면 구석에서 팝업이 뜨고 사라지며 "지금 이 순간도 다른 사람이 결과를 받고 있다"는 실시간 현장감을 만든다.

### 전략

우하단 고정 위치에 카드 형태의 팝업이 15~45초 랜덤 간격으로 나타났다가 3.5초 후 사라진다. 간격이 너무 짧으면 방해가 되고, 너무 길면 없는 것과 같다.

**팝업 문구 유형**

유형 1 — 결과 달성 알림 (가장 효과적)
```
🎉 경기도 남성 · 방금 상위 4.2% 달성
🎉 서울 여성 · 방금 상위 11.7% 판정
```

유형 2 — 유행 압박 문구
```
🔥 오늘 벌써 2,847명이 확인했어요
🔥 지금 이 시간 가장 많이 공유되는 중
```

유형 3 — 희소성 자극
```
⭐ 오늘 상위 1% 달성자: 23명
⭐ 방금 전설 등급(상위 1%) 판정이 나왔어요
```

유형 4 — 사회적 증거
```
👥 친구 링크로 접속한 사람이 많아요
👥 지금 단체로 도전 중인 팀이 있어요
```

**설계 규칙**  
팝업은 3.5초 이상 머물지 않아야 한다. 닫기 버튼은 제공하되 작게 만든다. 퀴즈 진행 중에는 팝업을 멈춰 집중을 방해하지 않는다. 결과 확인 후에는 공유 유도형 문구로 전환한다.

## 5. 퀴즈 진행 중 동시 참여자 표시

### 목표
혼자 하는 것이 아니라 지금 이 순간 수백 명이 같이 풀고 있다는 연대감과 경쟁심을 동시에 자극한다.

### 전략

퀴즈 화면 하단에 고정 바를 하나 추가하고 "지금 [N]명이 함께 풀고 있어요" 문구를 표시한다. 이 숫자는 시간대별 기댓값을 따르되 5초마다 ±2~4로 자연스럽게 변동한다.

**변형 문구 (문항 번호에 따라 동적으로 변경)**

```
Q1~Q5:  "지금 [N]명이 함께 시작했어요"
Q6~Q15: "지금 [N]명이 함께 풀고 있어요"
Q16~Q20: "[N]명이 곧 결과를 받아요"
Q21~Q25: "[N]명이 지금 결과 직전이에요!"
```

마지막 5문항에서 숫자를 약간 줄이고 "결과 직전" 문구로 바꾸면 완주 긴장감이 높아진다.

## 6. 랜딩 페이지 FOMO 카피라이팅

### 목표
화면에 표시되는 문구 자체가 압박감을 만들어야 한다.

### 현재 문구 vs 개선안

**현재 배지 문구**
```
🔥 지금 실시간 참여 중
```

**개선된 FOMO 배지 문구 (A/B 테스트 권장)**
```
안 1: 🔥 오늘만 벌써 2,847명 참여
안 2: 📲 친구들이 이미 하고 있어요
안 3: ⚡ 지금 이 순간 247명 테스트 중
안 4: 🏆 오늘 상위 1% 달성자 벌써 23명
```

**서브카피 개선안**

현재:
```
25개의 정밀 질문으로 전국 참여자 중
당신의 정확한 순위를 확인하세요
```

개선:
```
전국 5만 명이 이미 확인한 그 순위.
나는 몇 번째일까?
```

또는:
```
어제 하루에만 3,200명이 결과를 공유했어요.
당신 친구도 이미 했을지 모릅니다.
```

## 7. 순위 변동 알림 (결과 화면)

### 목표
결과를 본 후에도 자리를 뜨지 않고 공유하도록 만드는 긴장 유지 장치.

### 전략

결과 화면에 진입한 뒤 30~90초 랜덤 딜레이 후 "순위가 소폭 변동했어요" 알림을 표시한다. 방향은 반드시 **하락**으로 설정한다.

```
"상위 7.34% → 7.41%로 조정됐어요"
"새로운 참여자가 당신 앞에 3명 추가됐어요"
"지금 공유하지 않으면 순위가 더 내려갈 수 있어요"
```

하락 방향이 핵심이다. 상승하면 안도하고 머물지만, 소폭 하락하면 "지금 공유해서 기록해둬야겠다"는 손실 회피 심리가 발동한다.

## 8. 화면별 구현 우선순위

초기 단계에서 모든 기능을 동시에 넣으면 과부하가 온다. 아래 순서로 단계별 구현을 권장한다.

**1단계 (필수 — 런치 전 반드시)**
- 누적 참여자 카운터 (localStorage 연동)
- 시간대별 실시간 접속자 수 표시
- 랜딩 카피라이팅 개선

**2단계 (런치 후 1주 내)**
- 활동 알림 토스트 팝업
- 실시간 결과 피드 마퀴
- 퀴즈 중 동시 참여자 바

**3단계 (바이럴 안정화 후)**
- 순위 변동 알림
- 지역별 실시간 통계
- "오늘 상위 1% X명" 희소성 카운터

## 9. 반드시 지켜야 할 현실감 규칙

**숫자의 불규칙성**  
모든 숫자는 고정값이 아닌 범위 내 랜덤값이어야 한다. "현재 347명"이 새로고침해도 똑같이 347명이면 3초 만에 가짜임을 알아챈다.

**시간대 정합성**  
새벽 4시에 400명 접속 중은 말이 안 된다. 시간대별 패턴을 한국 실제 인터넷 트래픽에 맞게 설정해야 한다.

**지역 분포의 현실성**  
결과 피드에서 제주도가 서울보다 자주 나오면 이상하다. 실제 인구 비율대로 가중치를 설정한다.

**과도한 빈도 금지**  
토스트 팝업이 5초마다 뜨면 스팸처럼 느껴진다. 15~45초 랜덤 간격이 적절하다. 너무 자주 나오면 오히려 신뢰를 떨어뜨린다.

**세션 간 연속성**  
localStorage를 활용해 참여자 수가 재방문 시에도 줄지 않도록 한다. 어제 봤던 숫자보다 오늘 숫자가 작으면 즉시 의심받는다.

## 10. 법적·윤리적 고려사항

이 전략들은 실제로 수많은 서비스(Booking.com의 "지금 X명이 보고 있어요", Airbnb의 "최근 X번 예약됨", 쇼핑몰의 "현재 재고 X개")에서 광범위하게 사용되고 있다.

다만 다음 기준을 지키는 것이 장기적으로 유리하다.

첫째, 결과 수치(백분위, 등수)는 절대 허위로 생성하지 않는다. 소셜 프루프 숫자는 시뮬레이션이지만 개인의 점수 결과는 반드시 실제 알고리즘 기반이어야 한다.

둘째, 실제 트래픽이 늘어나기 시작하면 시뮬레이션 비중을 줄이고 실제 데이터를 점차 반영한다.

셋째, "현재 X명 접속 중" 같은 문구는 "약 X명" 또는 "지금 이 시간대 기준"으로 표현하면 법적 허위 표시 논란을 줄일 수 있다.
